# ClearEarth Frontend — Detailed Code File Reference

**Project:** `clearearth-frontend` (web app) — plus a short section on the separate `clearearth-mobile` driver app.
**Scope:** every code file under `src/` (892 `.js/.jsx/.ts/.tsx` files). Binary assets under `src/assets/` are omitted. `frontend-code-files.txt` (next to this file) lists every code path, one per line.
**Last full rewrite:** 2026-11-20 — regenerated from source: **148 routes**, **179 view files**, **371 `ApiService` methods**, 27 ERP-specific components, 46 support files (context / hooks / utils / constants / theme).
**Companion:** `CODEBASE_DOCUMENTATION.md` — the backend: API reference, models, business flows. Tables in §3, §5, §6, §7 are generated by parsing the code; §1, §2, §4 and §8–§10 are hand-written and verified against it.

> Since the 2026-07 version the app gained: the **HR** area (employees, attendance, leave, payroll, departments), **commissions**, **certificates**, the reworked **accounts** area (vendor bills, supplier payables / debit notes / advances, credit notes, cash & bank, bank reconciliation, payment receipts), **inspection location share**, role dashboards for accounts / HR, and push-token support for the mobile app.

## 2. Application architecture

### 2.1 Boot sequence
`src/main.jsx` installs the **chunk-reload handler** (`utils/chunkReload.js` — after a deploy, a stale lazy chunk triggers one automatic reload), starts the **MSW** mock service worker (`api/mocks/browser`, `onUnhandledRequest: 'bypass'`, so real API calls pass through), then renders:

`CustomizerContextProvider` → `AuthProvider` → `SocketProvider` → `Suspense` → `App` (`ThemeProvider` + RTL + `CssBaseline` + `RouterProvider`).

### 2.2 Routing and guards
- `src/routes/Router.js` (`createBrowserRouter`): every page is lazy-loaded through `Loadable(lazyWithChunkReload(...))`. The root layout `FullLayout` is wrapped in `ProtectedRoute`; auth pages use `BlankLayout`. Full list in §3.
- Route guards (`src/components/auth/`): `ProtectedRoute` (must be logged in), `RequireAdmin` (admin / tenant_admin / super_admin), `RequireNotDriver`, `RequireDealViewAccess` (operations roles may list deals but not open deal detail), `RequireInvoiceGenerator` (blocks sales, sales manager, operations from creating proforma / tax invoices), `RequireQuotationPoEditor`, `RequireWorkOrderCreator` (sales roles cannot create work orders). Their rules live in `utils/authHelpers.js` and mirror the backend (`roleAccess.js`).
- Unauthorised users are redirected to `/erp/dashboard`.

### 2.3 Auth, permissions and real-time
- `AuthContext` — `login`, `logout`, current user, `hasPermission(permission)`, `hasAnyPermission([...])`, `getScope(module)`, `hidesField(group)`; everything comes from the **effective access** returned by login / `me` (role permissions ± per-user overrides, data scopes, hidden field groups). No role names are used for access decisions. `components/auth/AccessLiveRefresh.jsx` reloads access instantly on the `access:changed` socket event (fallback: tab focus + every 2 min).
- `utils/authHelpers.js` — `userCan`, `userScope`, `userHidesField`, `canGenerateInvoice`, `canViewDealDetails`, `canModifyOrders`, `canCreateWorkOrder` — all permission/field-rule based.
- Route guards (`components/auth/`): `RequirePermission` (`permission` / `anyOf`), plus `RequireNotDriver` (`deals.read`), `RequireDealViewAccess`, `RequireQuotationPoEditor` (`orders.modify`), `RequireInvoiceGenerator` (`invoices.generate`), `RequireWorkOrderCreator` (`operations.create`).
- `services/api.js` — `ApiService` singleton: base URL `VITE_API_URL`, bearer token in `localStorage`, **single-flight silent refresh** on 401, forced login redirect when refresh fails, `getUploadUrl()` for `/uploads/…`, and one method per endpoint (§5). Errors are turned into plain language by `utils/formatApiError.js`.
- `SocketContext` — Socket.IO client authenticated with the access token; consumers subscribe with `on(event, handler)` (dashboard live refresh, notifications). `RealtimeNotificationToast` shows incoming events; the header bell (`layouts/full/vertical/header/Notifications.js`) loads `/notifications` and also polls every 60 s as a fallback.

### 2.4 Navigation (sidebar)
`layouts/full/vertical/sidebar/ErpMenuItems.js` builds the menu, gated **only by permissions**: each item has `permission` (must hold) or `anyOf` (hold at least one) — no role lists. `sidebar/menuAccess.js` (`filterMenu`, `isItemVisible`) hides items the user cannot use and any section heading with nothing visible. Top-level groups:

- **Dashboard**, **My Commissions**
- **Clients & Vendors** (Contacts, Clients, Vendors) · **Leads & Deals**
- **Service and Purchase** — Quotations (Service / Client purchase), Orders (Clients Service, Clients Purchase, Vendor Purchase)
- **Accounts** — Sales & Receivables (Proforma, Tax Invoices, Credit Notes, Receivables, Receive Payment, Payment Receipts) · Purchases & Payables (Vendor Bills, Supplier Payables, Supplier Debit Notes, Supplier Advances, Older PO Payables) · Expenses · Cash & Bank (Transfers, Bank Reconciliation) · General Ledger (Chart of Accounts, Journal) · Financial Reports (Trial Balance, General Ledger, Income Statement, Balance Sheet, Cash Flow, Changes in Equity, VAT)
- **Operations** — Deals, GRN, Inventory, Work Orders, **Certificates** (Requests, Register)
- **Catalog & settings** — Products & Services, Terms & Conditions, Inspection Requests, Roles & Access, Users, Company Settings, Fiscal Years, Commission Settings, Carbon Footprint Factors
- **My HR** (always visible): My Profile, My Attendance, My Leave, My Payslips
- **HR management** (permission-gated): Employees (+ Profile Changes, Departments), Attendance Management, Leave, Payroll

The `Menudata.js` under `horizontal/navbar` and `MenuItems.js` are template leftovers.

### 2.5 Roles & Access UI
- `/erp/roles` (`views/erp/roles/RoleList.jsx`) — built-in and custom roles as cards (users, permission coverage, *Customised* badge) with Edit access, Clone, Reset to default, Delete.
- `/erp/roles/create`, `/erp/roles/edit/:id` (`RoleForm.jsx`) — role editor with tabs **Permissions** (`components/erp/access/PermissionMatrix.jsx`: modules × View/Create/Edit/Delete/Approve + special actions, search, filters, presets, change highlighting, auto-View dependency), **Data scope** (`DataScopePanel.jsx`), **Field visibility** (`FieldVisibilityPanel.jsx`), **Users**, **History** (audit trail). Sticky save bar with unsaved-change count, *Review & save* diff dialog (`AccessDiffDialog.jsx`) and *Reset to default*.
- `components/erp/access/UserAccessDialog.jsx` — per-user grants/revokes on top of the role (reason + expiry), opened from *Users → Manage access* and the user form.
- API methods: `getAccessCatalog`, `saveRoleAccess`, `cloneRole`, `resetRole`, `getRoleUsers`, `getPermissionHolders`, `getAccessAudit`, `getUserAccess`, `saveUserAccessOverrides`.

### 2.5 Dashboards
`views/erp/dashboard/DashboardRouter.jsx` fetches `GET /dashboard/overview` (one shared date-range filter, default "this month", live-refreshed via Socket.IO) and renders by role: `admin` / `tenant_admin` → `AdminDashboard`; `super_admin` → `SuperAdminDashboard`; `sales` → `SalesDashboard`; `sales_manager` → `SalesManagerDashboard`; `inspection_team` → `InspectionDashboard`; `operations_manager` → `OperationsDashboard`; `accounts` → `AccountsDashboard`; `driver` → `DriverPickupList`. HR widgets (`views/erp/hr/HrDashboardWidgets.jsx`) are added for HR users.

### 2.6 Cross-cutting UI conventions
- **Approval workflows:** `ApprovalWorkflowDialogs`, `ApproveQuotationConfirmDialog` (request approval / approve / PIN) shared by leads, deals, quotations, purchase orders.
- **Money & accounts:** `PaymentRecordingFields`, `PaymentHistoryDialog`, `PaymentReceiptDocument`, `CascadingAccountSelect` + `utils/accountTree.js` (parent → sub-account pickers), `AmountBreakdownDialog` / `GlAmountLink` + `utils/glLink.js` (drill-down from any figure to the General Ledger), `PayeeSelect`.
- **Dates:** always use `utils/dateLocal.js` (local-calendar helpers) — `toISOString().slice(0,10)` shifts dates by a day in UTC+4.
- **Phone / units / uploads:** `utils/phone.js` (9–16 digits, optional leading `+`), `utils/uom.js` + `useUnitsOfMeasure`, `utils/uploadFileTypes.js`.
- **Maps:** `utils/googleMapsLoader.js` (`VITE_GOOGLE_MAPS_API_KEY`), used for location share and pickup maps.

## 4. ERP feature map

| Area | Where it lives (`src/views/erp/…`) |
|---|---|
| CRM | `contacts`, `companies`, `suppliers`, `leads`, `products`, `terms`, `deals` (List / Form / View) |
| Quotations & orders | `quotations` (service quotations, client/vendor purchase quotations), `purchase-orders` (client & vendor POs, purchase bills) |
| Operations | `work-orders` (drag-reorder tasks, driver assignment, expense evidence, completion PDF, purchase bills), `grn` (also hosts `InventoryList`), `inspection-requests`, `driver` (pickup start/complete) |
| Certificates | `certificates` (requests, verification, register, PDFs) |
| Accounts | `accounts`, `receivables`, `payables`, `proforma-invoices`, `tax-invoices`, `cash-bank`, `reports`, `account` — invoices, credit notes, receipts & statements, vendor bills, debit notes, supplier advances, expenses, transfers, bank reconciliation, chart of accounts, journal, financial reports |
| HR | `hr/employees` (list, form, detail with child records / assets / notes / documents), `hr/attendance` (my, sheet, regularization), `hr/leave`, `hr/payroll` (runs, payslips), `hr/departments`, `hr/components` |
| Commissions | `commissions` (my commissions, settings, payouts) |
| Admin | `roles`, `users`, `settings` (`CompanySettings`); the fiscal-year, carbon-factor and commission-settings screens are reached through the routes in §3 |
| Dashboards | `dashboard` (§2.5) |

## 10. Build, deploy and conventions

- **Build:** `npm ci && npm run build` → `dist/`. nginx serves `dist/` (immutable `/assets/`, no-cache `index.html`); proxies `/api`, `/socket.io`, `/system-console`, `/uploads` to the API. The Google Maps key is injected at build time into `.env.production`.
- **After a deploy:** open tabs hold old hashed chunks; `chunkReload.js` reloads once automatically instead of showing an import error.
- **Environments:** live `https://recyclingerp.com`; a dev copy of the stack runs on the live server (`:3335`, and `dev.recyclingerp.com` once DNS is set). Details in `CODEBASE_DOCUMENTATION.md` §14.
- **Conventions:** pages are `XList` / `XForm` / `XView` triplets per module; all API access goes through `apiService`; permissions via `useAuth().hasPermission(...)`; role-restricted routes use the `Require*` guards; money is formatted from API decimals; dates via `dateLocal.js`.
